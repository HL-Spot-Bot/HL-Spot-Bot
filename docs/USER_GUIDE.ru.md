# HL-Spot — Руководство пользователя

Версия 1.0.2

HL-Spot — это торговый бот для **Hyperliquid**: spot- и бессрочные (perp) рынки, несколько пар,
автоматические и ручные ордера. Он работает **на вашем собственном компьютере** (Windows, Linux или Docker), а
управляете вы им из веб-браузера.

> **Сайт**: https://hlspot.com
> **Скачать**: https://github.com/HL-Spot-Bot/HL-Spot-Bot
> **Поддержка**: HL-spot@cmails.eu

---

## 1. Перед началом

Вам понадобится:

- компьютер с 64-битным процессором x86 (x86_64) под управлением **Windows** или **Linux**, либо любая
  машина с **Docker**;
- или аккаунт **Flux**, чтобы запускать его в облаке (раздел 16);
- аккаунт **Hyperliquid** со средствами (ваш основной wallet);
- кошелёк, способный **«подписать сообщение»** адресом вашего основного wallet. Проще всего
  использовать расширение браузера (MetaMask, Rabby…): бот откроет его за вас. Любой другой кошелёк работает
  через копирование и вставку;
- подключение к Интернету.

## 2. Безопасность: что нужно знать

- HL-Spot принимает только ключ **API wallet** от Hyperliquid. **Никогда не вводите приватный ключ
  вашего основного wallet.** API wallet может торговать от вашего имени, но не может выводить ваши средства.
- Ключ API wallet хранится на вашем компьютере в **зашифрованном** виде. Он **никогда не отправляется** на
  сервер лицензий.
- Ваш основной wallet используется только для **подписи сообщений** (создание аккаунта, забытый пароль,
  BTC-адрес, удаление аккаунта). Подписанное сообщение — это не транзакция: оно ничего не стоит
  и не перемещает средства.
- Веб-страница бота защищена вашим паролем. Предпочтительно открывать её на машине бота
  (`http://localhost:60000`): с другой машины вашей сети страница не
  шифруется (см. раздел 15).

## 3. Создайте API wallet в Hyperliquid

1. Перейдите на **https://app.hyperliquid.xyz/API** и подключите ваш основной wallet.
2. Задайте имя для API wallet, затем сгенерируйте его.
3. **Скопируйте показанный приватный ключ** и сохраните его в надёжном месте: Hyperliquid показывает его только один раз.
4. Авторизуйте API wallet (подпись вашим основным wallet).
5. Запишите **дату истечения срока действия** API wallet, которую показывает Hyperliquid.

В HL-Spot вы введёте: **адрес основного wallet** (0x…) и **приватный ключ API
wallet**.

## 4. Установите HL-Spot

Скачайте файл для вашей системы и соответствующий файл `.sha256` по адресу
https://github.com/HL-Spot-Bot/HL-Spot-Bot. Файл `.sha256` позволяет проверить, что загруженный файл
не повреждён.

### Windows

1. Распакуйте `HL-Spot-1.0.2-prod-windows-x64.zip`.
2. В распакованной папке запустите **`HL-Spot.exe`**. Откроется окно консоли: не закрывайте его, пока
   работает бот.
3. Откройте **http://localhost:60000** в браузере.

### Linux (Ubuntu 22.04, 24.04, 26.04, Debian 12 или новее)

```
unzip HL-Spot-1.0.2-prod-linux-x64.zip
cd HL-Spot-1.0.2-prod-linux-x64
./hl-spot
```

Затем откройте **http://localhost:60000** в браузере.

### Docker

```
docker load -i HL-Spot-1.0.2-prod-docker-x64.tar.gz
docker run -d --name hl-spot --restart unless-stopped -p 60000:60000 \
       -e TZ=Europe/Paris -v hl-spot-data:/data hl-spot:1.0.2
```

- `-p 60000:60000` обязателен для доступа к веб-странице.
- `TZ` задаёт часовой пояс (UTC, если не указан).
- Ваши данные остаются в томе `hl-spot-data`, даже если контейнер удалён или образ
  обновлён.
- `docker stop hl-spot` корректно останавливает бота.

Затем откройте **http://localhost:60000** (или `http://<machine address>:60000`).

### Где хранятся ваши данные

Ваши данные (настройки, зашифрованный ключ, база данных, журнал) хранятся **вне программы**:

| Система | Папка |
|---|---|
| Windows | `%LOCALAPPDATA%\HL-Spot` |
| Linux | `~/.local/share/hl-spot` |
| Docker | том `/data` |

Переустановка или обновление программы никогда их не затрагивает.

## 5. Первый запуск

Первая страница — **Первый запуск**. Выберите:

- **Создать аккаунт**, если вы новый пользователь;
- **У меня уже есть аккаунт**, если у вас уже есть аккаунт HL-Spot (новый компьютер,
  переустановка).

### Создать аккаунт

1. **Адрес кошелька**: адрес вашего основного wallet (0x…).
2. **Приватный ключ API wallet**: ключ, скопированный в разделе 3. Прежде всего он проверяется в
   Hyperliquid.
3. **Пароль**: не менее 8 символов, включая заглавную букву, строчную букву,
   цифру и специальный символ. Он защищает и ваш аккаунт HL-Spot, и веб-страницу
   бота.
4. **Подпись основного кошелька**:
   - **Подписать моим кошельком**: бот открывает расширение вашего кошелька; проверьте адрес и
     подтвердите подпись;
   - или **Получить сообщение для подписи**: скопируйте сообщение без изменений в ваш кошелёк, подпишите его и
     вставьте подпись (0x…). Сообщение действительно 15 минут.
5. Нажмите **Создать аккаунт**.

Начинается ваш **бесплатный пробный период на 7 дней**. Он предоставляется только один раз на wallet и на
установку. Торговля начинается после проверки вашего аккаунта Hyperliquid.

### У меня уже есть аккаунт

Введите адрес вашего кошелька и пароль. Эта установка регистрируется, а
предыдущая освобождается (**одна смена установки в 30 дней**).

Меню вверху даёт доступ к следующим страницам:

| Страница | Назначение |
|---|---|
| 📊 Панель | Балансы, состояние рынка, состояние каждого spot-цикла |
| 📈 Статистика | Результаты spot- и perp-циклов по периодам |
| 🧩 Торгуемые пары | Spot- и perp-пары, настроенные для бота, и их параметры |
| 🟣 Perp-циклы | Входы, take-profit, stop-loss и закрытия perp-пар |
| 🖐️ Ручные ордера | Выставьте ордер вручную; затем бот ведёт цикл, как и остальные |
| 🌐 Пары Hyperliquid | Список spot- и perp-пар Hyperliquid; отсюда можно добавить пару в бота |
| ⚙️ Настройки | Глобальные настройки (применяются без перезапуска, кроме порта и адреса прослушивания) |
| 📝 Журнал | Ошибки (и предупреждения, если включено) |
| 🔑 Аккаунт Hyperliquid | Wallet, ключ API wallet, дата истечения срока действия |
| 📜 Лицензия | Лицензия, подписка, оплата, установка, удаление аккаунта |

Бот торгует, только если **ваш аккаунт Hyperliquid проверен** и **ваша лицензия
действительна**. Без действующей лицензии доступны только страницы «Аккаунт Hyperliquid» и «Лицензия».

Когда бот прекращает торговлю (лицензия истекла, срок действия API wallet истёк или он отклонён), он **не
трогает уже открытые ордера и позиции**: ответственность за них остаётся на вас.

В следующих подразделах объясняется, как бот принимает решения, а затем описывается каждое поле страниц
**Торгуемые пары** и **Настройки**.

### 6.1 Анализ рынка: BULL, BEAR или RANGE

Перед каждой покупкой (spot) или входом (perp) бот анализирует **саму пару** по свечам
этой пары:

1. Он загружает последние свечи в количестве **Количество загружаемых свечей** (параметр `LIMIT`)
   с **Интервал свечей** пары (пусто = глобальный параметр **Интервал свечей**).
2. **Текущая цена** — это цена закрытия самой последней свечи.
3. Он вычисляет три скользящие средние по ценам закрытия: **MA4**, **MA8** и **MA12** (их
   количество свечей задаётся в **Настройки → Анализ рынка**).
4. Он определяет тип рынка в следующем порядке:
   - **RANGE**, если MA12 плоская: за последние периоды (**Проверяемых периодов MA12**) MA12
     изменилась не более чем на **Порог MA12 для RANGE (%)** между своим минимальным и максимальным значением;
   - иначе **BULL**, если MA4 > MA8 > MA12;
   - иначе **BEAR**, если MA4 < MA8 < MA12;
   - иначе **RANGE**.
5. Он также вычисляет **диапазон**: максимальную и минимальную цену закрытия за последние свечи
   в количестве **RANGE - периоды диапазона**. Его амплитуда равна максимум − минимум.

Затем каждая пара использует **свои собственные параметры для определённого типа рынка** (блок BULL, BEAR или
RANGE пары). Если анализ не удался (Hyperliquid недоступен), ничего не выставляется,
и бот повторяет попытку при следующем проходе.

### 6.2 Spot-цикл, шаг за шагом

Spot-цикл — это одна покупка, за которой следует одна продажа того же количества.

1. **Когда.** Бот проверяет каждую включённую spot-пару каждые **Короткая пауза цикла покупок (мин)**.
   Попытка покупки выполняется, когда:
   - пара не находится на паузе (см. шаг 6);
   - с предыдущей попытки по этой паре прошло не менее **наименьшего** из трёх значений
     **Интервал между покупками (мин)** пары (BULL, BEAR, RANGE), независимо от
     текущего рынка. Первая попытка после запуска бота ожидает **Задержка перед первой покупкой (мин)**.
2. **Разрешено?** Покупки должны быть включены глобально (**Покупки включены (глобально)**) **и** в
   блоке пары для текущего рынка (**Покупки включены**). Если нет, попытка засчитывается, но
   ничего не выставляется.
3. **Цены.** При *P* = текущая цена:
   - цена покупки = *P* + **Offset покупки**; целевая цена продажи = *P* + **Offset продажи**;
   - при **Единица offset** `abs` offset задаются в USDC; при `pct` — в % от *P*;
   - **на рынке RANGE** offset **динамические**: покупка = *P* − *d*, продажа = *P* + *d*,
     где *d* = амплитуда диапазона × **RANGE - % используемого диапазона** / 100 / 2. Статические
     offset RANGE пары используются, только если диапазон невозможно вычислить (амплитуда 0).
4. **Количество.** Сумма = **% баланса USDC** × **доступные** USDC (не занятые
   открытыми ордерами). Количество = сумма / цена покупки, округлённое **вниз** до шага размера
   пары. Если стоимость ордера ниже **Минимальная сумма ордера (USDC)** (не менее 10 USDC,
   минимум Hyperliquid), покупка отклоняется, и в журнале появляется «Value too low».
5. **Ордер.** Лимитный ордер на покупку выставляется по цене покупки. Цикл отображается на
   Панели как **Ожидает покупки**, с уже записанной целевой ценой продажи.
6. **Пауза.** После каждой попытки, выставлен ордер или нет, пара ожидает **Пауза после попытки (мин)**
   блока текущего рынка.
7. **Покупка исполнена.** Бот узнаёт об этом из истории Hyperliquid, загружаемой каждые
   **Интервал запросов к Hyperliquid (мин)**. Цикл переходит в состояние **Ожидает продажи**. Частично
   исполненная покупка, которая ещё открыта, остаётся в состоянии **Ожидает покупки**.
8. **Продажа.** Цикл продаж (каждые **Интервал цикла продаж (с)**) выставляет лимитный ордер на продажу по
   **целевой цене продажи, записанной на шаге 3**. Он продаёт фактически полученное количество:
   Hyperliquid взимает комиссию за покупку в купленном токене, поэтому бот продаёт купленное количество
   за вычетом этой комиссии, округлённое вниз до шага размера. Небольшой остаток может остаться в вашем wallet;
   его продаст один из последующих циклов, когда позволит баланс.
   - Цена продажи не пересчитывается. Если рынок уже выше неё, продажа
     исполняется немедленно по рыночной цене (лучше, чем планировалось).
   - Если баланса недостаточно, бот повторяет попытку; после 3 попыток проблема
     записывается в журнал как **ошибка**.
9. **Продажа исполнена.** Цикл переходит в состояние **Завершён**. Прибыль рассчитывается по фактическим
   цене и количеству продажи и фактическим комиссиям: проданное количество × (цена продажи − цена покупки) − комиссия
   за покупку − комиссия за продажу.

Переключатели **Продажи включены** в настоящее время ни на что не влияют: после исполнения покупки продажа
выставляется всегда.

**Пример расчёта (RANGE).** Текущая цена 85 000; за последние 20 свечей максимальная
цена закрытия 85 200, минимальная 84 770: амплитуда 430. При **RANGE - % используемого диапазона** =
75: *d* = 430 × 75 / 100 / 2 = 161,25. Покупка по 85 000 − 161,25 = 84 838,75; целевая продажа по
85 000 + 161,25 = 85 161,25. При **% баланса USDC** = 5 и 400 доступных USDC: 20 USDC,
то есть 20 / 84 838,75 = 0,0002357 базового токена, с округлением вниз до шага размера пары.

### 6.3 Perp-цикл, шаг за шагом

Perp-цикл — это один вход (long или short), затем выход по take-profit, stop-loss или закрытию.

1. **Когда.** Те же правила, что и для spot: каждая включённая perp-пара проверяется каждые
   **Короткая пауза цикла покупок (мин)**; пауза после каждой попытки (**Пауза после попытки (мин)** блока текущего
   рынка) и наименьшее из трёх значений **Интервал между входами (мин)**.
2. **Перед любым входом, при каждом проходе** бот применяет текущее **Направление** к циклам,
   уже открытым по паре:
   - направление **none**: ещё не исполненные входы отменяются; открытые позиции обрабатываются согласно
     **Направление установлено в «none» при открытой позиции** (`keep_tp_sl` = оставить take-profit
     и stop-loss на месте; `close_market` / `close_limit` = закрыть позицию);
   - направление, **противоположное** открытому циклу (например, `short` при открытом long):
     ещё не исполненный вход отменяется, открытая позиция закрывается согласно
     **Закрывать при развороте** (`market` = рыночный ордер; `limit` = лимитный ордер по текущей цене).
3. **Какая сторона.** `long` или `short`: эта сторона. `none`: без входа. `both`: согласно
   **Правило направления «both»**:
   - `first_filled`: выставляются вход в long и вход в short; первый исполненный отменяет
     другой;
   - `range_position`: long, если цена в нижней половине диапазона, short — в
     верхней половине; вне рынка RANGE входа нет;
   - `alternate`: сторона, противоположная предыдущему циклу пары.
4. **Фильтр funding.** Нет long, если ставка funding выше +**Порог funding (%)**; нет
   short, если она ниже −порога. Если funding недоступен, входа нет.
5. **Плечо и маржа.** При необходимости бот устанавливает для пары **Плечо** и
   **Режим маржи** на Hyperliquid перед входом.
6. **Цены и размер.** При *P* = текущая цена: вход = *P* + offset входа для стороны, take-
   profit = *P* + offset take-profit для стороны (USDC или % в зависимости от **Единица offset**).
   Используемая маржа = **% доступной маржи** × доступная маржа; размер = маржа × плечо
   / цена входа, с округлением вниз.
7. **Вход.** Лимитный ордер по цене входа. Когда он исполнен, бот выставляет
   **take-profit** (лимитный, reduce-only) по записанной цене и **stop-loss** (stop
   market, reduce-only) на расстоянии **Stop-loss (% от цены входа)** от фактической цены входа.
8. **Выход.** Цикл завершается, когда исполнен take-profit, stop-loss или закрытие. Рыночные
   ордера и ордера stop market допускают отклонение не более **Slippage market-ордеров (%)**.

Следите за perp-циклами на странице **🟣 Perp-циклы**.

### 6.4 Страница «Торгуемые пары»

Страница **🧩 Торгуемые пары** содержит список пар, настроенных для бота.

- **Добавить пару**: на странице **🌐 Пары Hyperliquid** нажмите **Добавить** в строке пары. Новая пара
  **отключена**; её spot-параметры предварительно заполнены значениями по умолчанию BULL / BEAR / RANGE со
  страницы **Настройки**. Perp-параметры необходимо ввести.
- **Изменить**: открывает параметры пары: общую часть, затем по одному блоку на каждый тип рынка
  (BULL, BEAR, RANGE). **Сохранить** проверяет каждое значение; неверные поля выделяются.
- Столбец **Конфигурация**: **заполнено** или количество полей, которые нужно **заполнить**. Пару
  можно включить, только когда она заполнена полностью.
- **Включить / Отключить**: торгуются только включённые и полностью заполненные пары. Включить можно только
  spot-пары с котировкой в USDC. Отключённая пара не выставляет новых входов, но **её открытые циклы продолжаются
  до их закрытия**.
- **Удалить**: возможно, только если у пары нет цикла в процессе. Сначала отключите её и
  дождитесь завершения её циклов.
- Изменения применяются при следующем проходе соответствующего цикла, без перезапуска.

**Offset** — цена покупки или входа = текущая цена + offset; цена продажи или take-profit =
текущая цена + offset. Отрицательный offset находится ниже текущей цены.

#### Параметры spot-пары

Общая часть:

| Поле | Значение |
|---|---|
| Единица offset | `abs` = offset в USDC; `pct` = offset в % от текущей цены |
| Интервал свечей | Свечи для анализа рынка этой пары; пусто = глобальный **Интервал свечей** |
| RANGE - % используемого диапазона | Динамические offset в RANGE = ± (амплитуда диапазона × этот %) / 2 |

Один блок для BULL, один для BEAR, один для RANGE:

| Поле | Значение |
|---|---|
| Покупки включены | Покупки разрешены, когда определён этот тип рынка |
| Продажи включены | В настоящее время не влияет: продажи выставляются всегда |
| Offset покупки | Цена покупки = текущая цена + этот offset (обычно отрицательный); в RANGE заменяется динамическим offset |
| Offset продажи | Целевая цена продажи = текущая цена + этот offset; в RANGE заменяется динамическим offset |
| % баланса USDC | Доля доступных USDC, используемая для каждой покупки |
| Пауза после попытки (мин) | Ожидание после каждой попытки покупки на этом рынке |
| Интервал между покупками (мин) | Минимальное время между двумя попытками покупки; используется наименьшее из трёх блоков |

#### Параметры perp-пары

Общая часть:

| Поле | Значение |
|---|---|
| Единица offset | `abs` = USDC; `pct` = % от текущей цены |
| Интервал свечей | Как для spot |
| Плечо | Ограничено максимальным плечом актива |
| Режим маржи | `cross` или `isolated` (некоторые активы требуют `isolated`) |
| Stop-loss (% от цены входа) | Ордер stop market на этом % от фактической цены входа |
| Порог funding (%) | Нет long, если funding > +порог; нет short, если funding < −порог |
| Slippage market-ордеров (%) | Максимальное допустимое отклонение для рыночных ордеров и ордеров stop market |
| Правило направления «both» | `first_filled`, `range_position` или `alternate` (см. 6.3); обязательно, как только блок использует `both` |
| Закрывать при развороте | `market` или `limit` |
| Направление установлено в «none» при открытой позиции | `keep_tp_sl`, `close_market` или `close_limit` |

Один блок для BULL, один для BEAR, один для RANGE:

| Поле | Значение |
|---|---|
| Направление | `long`, `short`, `both` или `none` (без входа) |
| Offset входа в Long / Offset take-profit для Long | Take-profit должен быть выше входа |
| Offset входа в Short / Offset take-profit для Short | Take-profit должен быть ниже входа |
| % доступной маржи | Доля доступной маржи, используемая для каждого входа, одинаковая для long и short |
| Пауза после попытки (мин) | Ожидание после каждой попытки входа на этом рынке |
| Интервал между входами (мин) | Минимальное время между двумя попытками входа; используется наименьшее из трёх блоков |

## 7. Лицензия и подписка

### Цены

| Подписка | Цена |
|---|---|
| 7 дней | 2 $ |
| 30 дней | 6 $ |

Оплаченный период добавляется к концу вашей текущей лицензии (или начинается с даты оплаты,
если лицензия уже истекла).

### Как оплатить

На странице **Лицензия**, в блоке **Подписка и оплата**:

1. выберите подписку, токен и сеть;
2. бот покажет **точную сумму**, **адрес получателя** и адрес, **с которого** вы должны
   **заплатить**. Сумма действительна **1 час** (меньше, если цена изменится более чем на
   10 %);
3. отправьте **ровно эту сумму**, в **этой сети**, **с wallet вашего аккаунта
   HL-Spot**;
4. платёж распознаётся автоматически (несколько минут в зависимости от сети), и
   лицензия продлевается.

Доступные токены и сети — те, что показаны на странице «Лицензия».

**Правила — прочитайте их перед оплатой:**

- платите **ровно** запрошенную сумму, не больше и не меньше; **сетевые комиссии оплачиваете вы**;
- платите **с wallet вашего аккаунта** (для BTC: с указанного вами BTC-адреса);
- платите в указанной сети, пока сумма действительна;
- платёж, не соответствующий этим правилам (неизвестный адрес, другая сумма, другая
  сеть, после истечения срока действия), **теряется: возврат не производится**.

### Оплата в BTC

Перед первой оплатой в BTC укажите ваш **BTC-адрес** на странице «Лицензия» (подтверждение
подписью вашего основного wallet). Платёж распознаётся, только если он отправлен **с этого BTC-адреса**:
в вашем BTC-кошельке выберите этот адрес в качестве источника платежа («coin
control»).

### Проверки лицензии

- Лицензия проверяется на сервере **каждые 6 часов**.
- Если сервер недоступен, бот продолжает работу до известной даты окончания
  лицензии.
- **За 24 часа до окончания**: предупреждение на веб-страницах и в Telegram.
- После окончания: **24 часа льготного периода** (торговля продолжается с предупреждением), затем торговля
  останавливается.
- Не переводите часы компьютера назад: если часы переведены назад более чем на 5 минут, торговля останавливается
  до следующей успешной проверки.

## 8. API wallet: истечение срока действия и замена

- Страница **Аккаунт Hyperliquid** показывает дату истечения срока действия вашего API wallet. При необходимости вы можете ввести
  её самостоятельно.
- В течение **последних 7 дней**: баннер на веб-страницах и ежедневное сообщение в Telegram.
- В дату истечения срока действия торговля останавливается. Создайте новый API wallet (раздел 3) и введите его ключ на
  странице **Аккаунт Hyperliquid**: торговля возобновится без перезапуска программы.
- Новый ключ должен принадлежать **тому же основному wallet**: адрес кошелька изменить нельзя.
- При запуске и каждые 24 часа бот проверяет в Hyperliquid, что API wallet по-прежнему
  принадлежит вашему wallet.

Страница **Лицензия**, **🗑️ Удалить мой аккаунт**: пароль + подпись вашего основного wallet.

- На этом компьютере адрес кошелька, ключ API wallet и пароль стираются;
  история торговли сохраняется.

## 14. Обновления и резервное копирование

- **Обновление**: установите новую версию (распакуйте её или загрузите новый образ Docker); ваши данные
  сохраняются (раздел 4).
- **Резервное копирование**: скопируйте папку с данными (раздел 4). Файл `.env` и файл `secret.key` идут
  **вместе**: зашифрованные значения из `.env` и базы данных невозможно прочитать без
  `secret.key`. Если `secret.key` утерян, эти значения (ключ API wallet, токен Telegram…) нужно

## 16. Запуск HL-Spot на Flux

[Flux](https://runonflux.com) — децентрализованное облако: оно сдаёт в аренду контейнеры на
серверах (узлах), которыми управляют третьи лица. HL-Spot может работать там круглосуточно без
вашего компьютера. Flux не зависит от HL-Spot и оплачивается Flux.

### Ключ вашего API wallet на Flux: прочитайте сначала

На Flux данные бота (`/data`: зашифрованный ключ API wallet **и** файл `secret.key`, который
его расшифровывает) находятся на серверах других людей, в копиях на 3 узлах. Тип приложения вы
выбираете при развёртывании:

- **Приложение «enterprise»** (узлы ArcaneOS) — рекомендуется: по заявлению Flux, операторы
  узлов не имеют доступа к данным приложения (зашифрованный диск, ограниченный root-доступ), а
  переменные окружения остаются закрытыми.
- **Обычное приложение**: оператор узла может прочитать `/data`, а значит, и ключ вашего API
  wallet; переменные окружения, включая код первого запуска, может прочитать любой. API wallet
  не может вывести ваши средства, но владелец его ключа может торговать на вашем аккаунте. На
  ваш риск.

Независимо от типа, вы можете в любой момент отозвать API wallet на Hyperliquid (раздел 3).

### Настройки приложения

| Поле Flux | Значение |
|---|---|
| Образ | `olivier1246/hl-spot:1.0.2` |
| Порт и порт контейнера | `60000` |
| Данные контейнера | `g:/data` (**обязательно**) |
| CPU | 0,2 |
| RAM | 300 МБ (увеличьте, если приложение перезапускается из-за нехватки памяти) |
| SSD | 3 ГБ |
| Экземпляры | 3 (минимум Flux) |
| Окружение | `HL_SPOT_SETUP_CODE=<ваш код>` (**обязательно**), `TZ=Europe/Paris` (необязательно) |

- `g:/data`: бот работает только на **одном** экземпляре; 2 других хранят синхронизированную
  копию данных и подменяют его, если он остановится. Никогда не используйте другое значение:
  бот работал бы на 3 машинах одновременно и выставлял бы каждый ордер 3 раза.
- `HL_SPOT_SETUP_CODE`: код из 12 символов или длиннее, отличный от вашего пароля. Без него
  любой, кто найдёт адрес приложения, мог бы создать аккаунт раньше вас.

### Первый запуск на Flux

1. Откройте адрес **https**, который Flux указывает для приложения.
2. Следуйте разделу 5 и введите свой код в поле **Код первого запуска**.
3. Используйте браузер с расширением вашего кошелька: бот подписывает им сообщение.

### Полезно знать

- Установка следует за данными: переход бота на другой узел не считается сменой установки
  (раздел 10).
- После перехода бот перезапускается с синхронизированной копии: проверьте свои открытые
  ордера на Hyperliquid.
- **Обновление**: замените образ на новую версию в настройках приложения на Flux.
- Страница доступна из Интернета: она защищена вашим паролем. Выберите надёжный.
